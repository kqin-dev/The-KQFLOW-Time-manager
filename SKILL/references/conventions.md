# 硬性约定

这些约定不是风格偏好，而是**违反就会重现历史 bug** 的规则。
改代码前先过一遍这一页。

## 1. 所有列位置按「显示宽度」算，绝不按 rune 下标

中文一个字占两列。本项目是三套坐标系混用出过事故的地方：

| 概念 | 含义 | 用错会怎样 |
| --- | --- | --- |
| 字节下标 | `len(string)` / `s[:n]` | 切在半个汉字上，行号与列位全错 |
| rune 下标 | `[]rune(s)` 的下标 | 中文处列位偏一半 |
| **显示宽度** | `lipgloss.Width(s)` / 逐 rune 累加 | ← **唯一正确的坐标** |

具体要求：

- 判断一行是否超宽、截断、补空格、算光标位置，**一律用显示宽度**。
- 需要切片时先转 `[]rune`，不要对 string 直接切片
  （`text[:cursor]` 用的是字节偏移，`cursor` 是 rune 下标时必然出错）。
- 带样式的字符串不能直接量宽度（ANSI 转义会让它偏大）。要量就先去掉样式，
  或者同时维护一份纯文本副本，用纯文本算宽度。本项目大量函数返回
  `(styled, plain)` 两份就是这个原因。
- 测试里核对列位置要用**按显示列取字符**的辅助函数（项目里叫 `cellAt`），
  不要直接索引 rune 切片——测试犯这个错会掩盖真实 bug。

## 2. 二级内容一律复用中间栏

用户明确要求过：不要另起「铺满屏幕的居中浮层」。

- **主看板**：三栏并排。
- **二级内容**（计时菜单、输入框、继承确认、帮助、设置、历史）一律只占中间栏，
  左右两侧的 TODO 与 GOAL 必须保持可见、边框完整。
- 统一入口是 `renderCenterBox(content)`；整页内容走 `pageContent(styled, plain, keepVisible)`。
- 内容高于中间栏时滚动，`keepVisible` 传光标所在行（设置页）或 -1。

**为什么**：早期弹窗是拼接在整个看板上的，必然横跨三栏，把左右面板的边框切出断口，
用户截图反馈「渲染坏了」。

## 3. 模态优先级

`View()` 的顺序是：`pick` > `editor` > `custom` > 各页面 > 看板。

选择框必须能盖住它下面的东西——因为「随手记没保存，是保存还是丢弃」这类提问
是在编辑器之上弹的。顺序写反了用户就看不到这个提问（真实踩过）。

## 4. 面板尺寸不要交给 Lipgloss 去夹

`Width(n)` / `Height(n)` 在 Lipgloss 里是**下限**：内容更宽会换行、更高会撑开。
`MaxWidth` 会切掉右边框，`Height(n).MaxHeight(n)` 一起用还会丢掉最后一行。

所以本项目的做法是：先按内容渲染，再**实测宽度做自校正**
（见 `panel()`），最后外层再用 `clipBlock` 兜底。新增面板请沿用这套，不要直接相信 `Width`。

## 5. 高亮 / 底色的宽度要贴合文字

选中行的底色用 `padTo(text, highlightWidth(text, inner))`，
**不要**用 `pad(text, inner)`——后者会把底色铺满整行，看起来像「光标拖了一行半」
（用户报过这个）。

## 6. 任何一行都不得超过内容宽度

超宽会被终端折成两行，看起来就像界面被撑破。
`contentWidth()` 是中间栏内容区的可用宽度，所有中间栏内容都要在它以内。
宽度在 60～160 列、高度 16～60 行之间都必须成立，小到 1×1 也不能溢出。

## 7. 多行编辑的提交键是 Ctrl+S，不是 Enter

随手记、自定义字条里，`Enter` 是**换行**（写日记时按回车不该被提交），
提交用 `Ctrl+S`。关闭用的 `esc` / `q` / `Ctrl+C` 在有未保存改动时都要先问。

单行输入框（标题、设置项）不受此限：那里的 `q` 是要输入的字符，不能吞掉。

## 8. 数据字段改动必须兼容老文件

- 加字段：用 `omitempty`，读老文件时补默认值。
- 改语义：在 `PruneOrphans()` 或读入路径里做迁移，并**保留用户数据**。
- 永远不要静默删除用户数据。删除必须由用户明确确认。
- 文本入库前统一走 `model.Sanitize`（清控制字符）。

## 9. 测试要用「入口清单」而不是只测报告的那一条

本项目最有效的一条经验：修「按 A 有保护、按 B 没有」这类 bug 时，
不要只给 B 补测试，而是**把所有同类入口列成一张表逐个断言**。

例：`TestEditorClosePathsAreAllProtected` 把 `esc` / `q` / `ctrl+c` / 菜单退出
四条路径都走一遍。以后新增入口就往表里加一行。

**保护类的改动，还要反向断言「该发生的确实发生」**：只断言「没被误触结束」的
测试，在实现坏成「永远结束不掉」时同样是绿的。所以每条入口都要再走一遍
「确认 → 真的归档」。见 `timer_stop_test.go`。

**测试要走用户真实能走通的路径**：交互一改（例如结束计时从按键改成 `p` 菜单），
测试里的按键序列就必须跟着改。把这条路径抽成 helper（如 `stopTimerViaMenu`），
否则测试验的是一条用户已经走不通的老路，绿得毫无意义。

## 10. 交付标准

- `gofmt -l cmd internal` 无输出；`go vet ./...` 通过；`go test ./... -count=1` 全绿。
- 新行为必须带测试。
- 提交信息用中文，写**根因**而不是现象。
- 如实说明哪些部分**没有**验证（尤其是真实终端观感）。
